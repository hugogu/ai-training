# FTN 1.1 改进说明

**日期：2026-10-17。** 本次按业务分析目标重写 FTN 1.0，并采用用户 Whimsical「Payout Transaction」的出款、退款场景及 1,000 / 15 / 10 USD 数据。新版重点是让图、表和业务规则互相对应。

## 1. 重心调整

| 调整 | 实际改善 |
| --- | --- |
| 移除请求、超时、重试、幂等、原子提交、观察快照等设计 | 文档围绕业务资金、账内变化、业务信息及账务映射展开 |
| 用场景卡限定业务假设 | 手续费谁承担、何时扣收、何时确认、是否退还都有明确口径 |
| 将业务事件作为图表共同索引 | 同一 E/R 编号关联箭头、分录和明细，减少靠位置猜对应关系 |
| 保留圆圈、箭头、机构外框及黄色便笺 | 延续原有画图风格；只增加必要的语义约定 |

## 2. 图示含义更明确

**账户与参与方分开。** 圆圈表示账户或明确的图外资金位置，外框表示参与方。客户可用、冻结、银行存款、渠道往来、收入与成本分别标明性质。

**银行账户与渠道往来分开。** 原来一个银行节点展开为 DBS 客户资金户和自有资金户；IBC 实际资金位置与 PSP 账上的 IBC 往来账户也分别表示。读者能判断本金和渠道费用分别从哪里支付。

**固定三种箭头。** F 实线为资金划转；L 长虚线为账内余额变化与分配；I 点线空心箭头为业务信息。付款完成通知可以关联一项业务事件，但自身不构成资金流。

**账内箭头有精确定义。** L 表示自然余额的转出和转入；借贷方向由账户性质确定。规范同时提供 Δbalance 公式和实际分录，避免把资产、负债、收入和费用的增减套用同一个借贷规则。

## 3. 示例如何贴近原业务

| 示例内容 | 新版安排 |
| --- | --- |
| 出款本金 1,000、客户服务费 15、渠道成本 10 USD | 全部保留；客户扣款 1,015，与 PSP 承担的成本 10 分开 |
| 出款分析 | E1 冻结、E2 调拨、E3 出款完成、E4 渠道扣费；对应原 JE 编号 |
| 订单与交易数据 | 保留 P00001 与 T00001-T00005，补上视角、业务事件和分录映射 |
| 退款分析 | R00001 关联 P00001；本金退回、渠道退费、客户退款确认与余额恢复分别表达 |
| 业务信息 | 使用付款指令、付款完成确认、扣费通知及退款通知，关联同一组业务事件 |

**图表不重复算钱。** 明确客户付款、渠道出款及资金调拨是不同视角，不能将三个 1,000 合成客户付款 3,000。客户退款同样不能加上 PSP 收到的渠道退费 10。

**表间编号已校准。** 客户付款与服务费对应 JE0002，冻结专用 JE0001，资金调拨对应 JE0003；订单号统一写 P00001。退款另建订单和分录，原付款记录保留。

**示例内部已闭合。** 出款客户余额减少 1,015，客户资金户流出 1,000，自有资金户流出 10；全额退款分别恢复。每笔借贷平衡，资金箭头与银行账户变动一致，账内箭头与自然余额变化一致。

**新增假设明确标出。** 主例选择逐笔后扣渠道费用、自有资金承担成本、退款三项全退。这些是说明用的政策选择，原板的待决问题没有被悄悄当作既定事实。

## 4. 对原板的修订及待确认处

退款原例中 1,010 对 1,000 的分录，改为本金 1,000 与退费 10 分开表达。采用渠道往来过渡后，收到本金只增加一次银行存款；客户待结算归集时使用渠道往来，避免重复借记银行。

冻结与退款待结算分开使用 2202-07、2202-04，名称与科目表同步。这是为本例统一的编码口径，正式科目与收入冲回政策仍需业务及财务确认。

## 5. 形式化与工具的取舍

保留小型形式模型及可选 JSON 表达，将校验改为对象引用、正整数金额、借贷平衡、事件前置、资金及账内投影一致性、明细对应和退款额度。移除执行尝试、请求证据与重复付款等旧检查。

本版提供两个完整机器样例：出款与全额退款。它们同时用于生成示例图、分录表及示例页面，减少手工重复录入。规范正文中的业务规则仍需人工评审，机器不判断费用政策或会计处理是否适用于真实业务。

PDF 和 SVG 使用同一套矢量场景。示例分录与事件来自同一份 JSON；测试还核对正文与图表中的事件、分录、金额及本次净变化。工具属于文档校验附录，不要求画图的人使用程序。

**版本迁移：**FTN 1.1 的模型结构不兼容 1.0；1.0 可从 Git 历史取得。旧版中的执行层示例不再出现在当前目录和入口中，避免混用。原 Whimsical 和 OmniGraffle 均未覆盖修改。

## 6. 可直接使用的材料

- 规范正文及 PDF：完整定义、图例、两类业务场景、分录、明细和规则。
- 独立改进说明及 PDF：本次范围调整、语义改善、原板修订及待确认处。
- 五幅可编辑 SVG：整体结构、符号图例、出款图、退款图、业务信息图。
- 出款及退款 HTML 示例页：将业务图、事件、分录、明细放在一起查看。
- JSON Schema、两个业务样例及校验测试：可选的文档一致性检查。

**正式试用前需确认的业务口径：**渠道调拨与出款的顺序、成本扣款资金来源及确认时点、客户服务费和渠道手续费的退款政策、待结算科目编码。这些是业务政策决策，不是系统交互设计。
