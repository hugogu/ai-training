# 从数值表示到 ONNX INT8 模型量化

适合已经理解训练、预测和分类评估，但还不熟悉浮点计算、部署运行时和模型压缩的读者。读完后进入 [ONNX_INT8量化.ipynb](ONNX_INT8量化.ipynb)；安装方法见 [README](README.md)。

这里用小模型把机制拆开观察。是否对大型视觉网络或 LLM 有实际收益，仍需要在目标模型与硬件上验证。

## 1. 训练完成后，模型究竟在计算什么

本例使用多层感知机 MLP（Multilayer Perceptron）：

```text
8×8 灰度图 → 展平为 64 个数 → 64 个隐藏单元 → 10 个类别输出
```

一层全连接网络的核心是：

$$
h=\operatorname{ReLU}(XW+b)
$$

若批次有 $N$ 张图，$X$ 形状为 $N\times64$，第一层权重 $W$ 为 $64\times64$，偏置 $b$ 有 64 个数。第二层再把隐藏表示映射为 10 类得分。权重是训练学到的常量；激活是每次输入经过各层计算产生的中间结果，随输入变化。

MLP 将图像展平，不直接使用卷积核或残差块。它适合展示矩阵乘法的量化，但不能据此推断 ResNet18 的速度和质量变化。

量化关注的是这些参数和计算所用的数值表示，并不重新定义真实标签，也不要求重新人工标注图片。

## 2. 位宽、浮点和整数怎样影响资源

| 表示 | 每个元素位数 | 可以先怎样理解 |
|---|---:|---|
| FP32 | 32 | 常用单精度浮点 |
| FP16 | 16 | 更少位数的浮点，表示范围和精度不同于 FP32 |
| BF16 | 16 | 指数位较多、有效精度较低的另一种浮点布局 |
| INT8 / UINT8 | 8 | 有符号 / 无符号整数，量化时另需缩放等信息 |
| 4 位量化 | 4 | 每个量化数值用更少位表示，具体编码依方案而定 |

FP32 不是“能精确存储任意小数”。浮点只表示有限集合，计算本来就可能舍入；量化进一步用更少、受约束的数值等级近似原值。

只计算一百万个权重的原始载荷，FP32 约 4 MB，INT8 约 1 MB。完整模型还包含计算图、偏置、缩放参数及未量化层，因此完整文件一般不恰好缩小四倍。

运行时还需要激活、临时缓冲、算子实现等。**文件字节数、峰值内存、延迟和准确率是四项独立指标**；一个变好不等于另外三个也变好。

## 3. 用一个数理解 scale 与 zero point

常见的均匀仿射量化可以简化写为：

$$
q=\operatorname{clip}\left(\operatorname{round}(x/s)+z,q_{min},q_{max}\right),
\qquad \hat{x}=s(q-z)
$$

- $x$：原始浮点数。
- $q$：保存或参与整数计算的编号。
- $s$：scale，正的缩放步长。
- $z$：zero point，让浮点 0 对应某个整数编号。
- clip：超出可表示编号范围时饱和到边界。
- $\hat{x}$：反量化后的近似值，不保证等于原值。

假设教学上选 `scale=0.01`、`zero_point=0`：`0.376 → 38 → 0.38`，误差为 0.004。若选 `scale=0.1`，则约为 `0.376 → 4 → 0.4`，误差变大，但相同整数范围能覆盖更宽的原值范围。

在未发生裁剪的理想最近舍入情况下，绝对误差一般不超过半个步长；超出范围被裁剪时，这个误差界限不再成立。

### 3.1 对称、非对称与通道粒度

对称量化通常围绕 0 选择整数范围；本例数值演示使用 `[-127,127]`、zero point 为 0。INT8 类型本身可存 `[-128,127]`，不要把演示的对称范围误当成类型范围。

非对称量化允许非零 zero point，以适应不围绕 0 的分布。UINT8 编号也能借助 scale/zero point 表示负的原始浮点值；“无符号编号”不代表原模型只能处理非负输入。

- per-tensor：一整块张量共享量化参数。
- per-channel：不同通道使用各自的量化参数，减少不同通道幅度差别带来的误差。

本例对权重启用 per-channel。量化轴和实际支持情况取决于算子、导出格式及运行时，不能把它理解成对每个单独元素任意分配一个 scale。

### 3.2 为什么 astype 不够

`astype(np.int8)` 只做普通类型转换，没有根据分布设计 scale/zero point，也没有改写模型计算图。把 0～1 的输入直接转整数会丢失大量信息，而且可能违反模型仍要求 float32 输入的接口。

真正模型量化还需处理整数运算、缩放衔接、偏置、算子支持等。ONNX 的具体规则可参考 [QuantizeLinear 规范](https://onnx.ai/onnx/operators/onnx__QuantizeLinear.html)。

## 4. 量化后怎样完成矩阵运算

忽略细节，一次乘加可以理解为：

$$
Y \approx s_xs_w\sum(q_x-z_x)(q_w-z_w)+b
$$

输入和权重先有整数表示，乘积通常用更宽的整数累加，结果再按需要缩放、反量化或重新量化。**INT8 推理不表示所有中间数和累加器也只有 8 位**。

能否更快，取决于是否有针对这些算子的整数内核，以及数据搬运、量化转换和调用开销。模型很小时，节省的计算可能不够抵消这些开销。

## 5. PTQ、动态量化、静态量化与 QAT

PTQ 是 Post-Training Quantization，训练后量化；QAT 是 Quantization-Aware Training，量化感知训练。

| 方法 | 权重 | 激活范围怎样确定 | 是否继续用损失训练 |
|---|---|---|---|
| 本例动态 PTQ | 转换时量化 | 推理时根据实际输入动态确定部分量化参数 | 否 |
| 本例静态 PTQ | 转换时量化 | 先跑代表性输入进行离线校准 | 否 |
| QAT | 训练时模拟量化效果 | 依具体训练方案估计或学习 | 是，借此适应误差 |

动态不表示模型权重在推理时重新学习；静态不表示所有输入必须固定大小。二者的区别主要在量化参数何时确定，以及相应的图与执行方式。

QAT 常用“伪量化”：前向模拟舍入和裁剪影响，训练过程使用相应的梯度近似。它通常仍需最后转换为目标低位部署表示，不是把训练张量直接全部改成整数即可反向传播。

本练习实际执行两种 PTQ，不执行 QAT。具体工作流见 [ONNX Runtime 量化指南](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)。

## 6. 校准数据是做什么的

静态量化需要了解中间激活的数值范围。校准器将代表性输入跑过网络，观察范围，再据此选量化参数；本例使用 MinMax 校准。

它通常不需要真实标签，因为这一步估计数值范围，不优化分类损失。它与 sklearn 的 `MinMaxScaler` 是不同操作：后者缩放表格特征，前者为内部低位表示提供范围依据。

本例取训练部分的前 128 条输入。由于数据已随机分层划分，它便于教学，但仍不保证覆盖所有重要分布；生产校准需要主动覆盖不同类别、场景、亮度或输入长度等。

异常大值会扩大 MinMax 范围，使普通数值之间的分辨率降低。范围定得过窄又会增加裁剪。校准样本不足、分布失配、某些层对扰动敏感，都可能造成质量下降。

严格的选择流程是：训练集学习权重，来自训练域的代表性输入做校准，验证集选择方案，最后测试集确认结果。不能反复按最终测试分数调整校准范围，却继续把它称为独立测试。

## 7. ONNX、运行时与 QDQ 分别是什么

| 对象 | 本练习中的作用 |
|---|---|
| scikit-learn 分类器 | 负责训练，原始参数保存在 Python 模型对象中 |
| skl2onnx | 把网络转换成 ONNX 图和参数 |
| ONNX 文件 | 表达算子、连接关系、参数和输入输出约定 |
| ONNX Runtime | 加载并执行模型的运行时 |
| Execution Provider | 将支持的计算交给某个执行后端，本例固定 CPU |
| QDQ | Quantize/Dequantize，通过节点标记量化及反量化边界 |

动态量化模型中可看到 `MatMulInteger`；静态 QDQ 图中可看到 `QuantizeLinear` / `DequantizeLinear`。运行时可能将合适模式融合到整数内核；图里出现 QDQ 并不自动证明目标硬件整条流程都在高速整数执行。

原图、量化图的接口仍可能是 float32 输入和浮点概率。接口类型与内部权重类型不同，不应因为是 INT8 模型就手动把输入转成 int8。

本例先检查 sklearn 与导出的 FP32 结果接近，才比较量化误差。否则，导出错误和量化误差会混在一起。

## 8. 怎样看懂练习的质量结果

假设只有四个测试样本：

```text
真实标签       [0, 1, 1, 0]
FP32 预测      [0, 0, 1, 0]   准确率 3/4
量化后预测     [1, 1, 1, 0]   准确率 3/4
```

准确率没变，但两个预测变了：一个正确变错误，一个错误变正确；前后预测一致率只有 2/4。

所以需要分开观察：真实标签准确率、关键类别召回、预测一致率、概率差异和逐条错误。即使 argmax 全相同，概率仍可能明显变化，影响阈值判定或后续排序。

本例数据为 sklearn digits 的 8×8 图像，不是 MNIST 的 28×28 图像。固定除以 16 将像素缩放到 0～1，最后输入为 `[N,64]`；标签顺序是数字 0～9。

## 9. 怎样比较性能才有意义

本例控制 CPU 后端、线程、输入和批量，预热后反复测 `session.run`。batch=1 更接近单条请求，batch=64 展示批量执行；两者不能混用比较。

- 延迟：一次调用多久。批量调用的延迟并非每张图片单独请求的延迟。
- 吞吐：单位时间处理多少样本。这里以批量数量除以调用时间估算。
- 轮均值中位数：每轮多次调用先求平均，再比较各轮均值的中位数。
- P95：95% 请求低于某个耗时，需要相应的单次分布统计；本例没有测这个指标。

本例不含下载、训练、导出、模型加载和图片预处理时间，也没有测峰值内存。单次调用只有微秒量级，系统负载和框架调用开销会影响比较，应多轮测量并保留范围。

动态量化的部分激活参数随实际批次变化，质量评估也要固定批次设置。本例用 batch=64 比较概率；换一个批次组合可能改变少量量化结果。

## 10. 如何联系到 LLM 的量化

LLM 有大量权重，还会有随上下文与批量增长的 KV cache，因此权重压缩不等于总内存同比缩小。

| 术语 | 含义与边界 |
|---|---|
| W4A16 | 通常表示权重 4 位、激活 16 位的方案类别，具体格式依实现 |
| W8A8 | 通常表示权重和激活各 8 位，不能仅凭名字断言累加或全部算子精度 |
| GGUF | 模型容器格式，可装不同量化类型，不是一种单独的量化算法 |
| QLoRA | 在量化且冻结的基础权重上训练 LoRA 等增量，本例 FP32 LoRA 不属于它 |

QLoRA、GPTQ、AWQ 等属于各有设计与硬件条件的方法，不能直接把本练习针对小 MLP 的 `quantize_dynamic` 调用视为通用 LLM 量化配方。相关定义可看 [QLoRA 原论文](https://arxiv.org/abs/2305.14314)与 [GGUF 格式说明](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md)。

## 12. 自测与参考解释

1. **为什么 8 位模型有 float32 输入？** 接口类型可以不变，图内部处理量化边界。
2. **没有标签能否校准？** 本例可以，校准估计激活范围；但质量评估仍需真实标签。
3. **文件减半能否推断速度快一倍？** 不能，硬件内核、转换、批量和运行时开销都影响速度。
4. **准确率相同是否表示行为相同？** 不能，新增错误和修复错误可能抵消，概率也可能漂移。
5. **INT8 每个权重一字节，为什么文件不是恰好四分之一？** 还有图、偏置、量化参数和未量化数据。
6. **把 `.onnx` 改名为 `.gguf` 能在另一运行时使用吗？** 不能，两种格式需要实际转换及兼容的模型与算子支持。
