# 从计算机视觉基础到 ResNet18 微调

适合已经知道训练集、特征、标签、损失和过拟合，但还没有系统学过计算机视觉和 PyTorch 的读者。读完后，接着学习 [ResNet18微调.ipynb](ResNet18微调.ipynb)；安装和运行方法见 [README](README.md)。

建议分两遍：先读第 1～6 节建立模型图景，再读第 7～11 节并对照 Notebook。无需先背网络全部参数或推导反向传播。

## 1. 计算机视觉在解决什么问题

图像是输入，任务决定输出的含义：

| 任务 | 典型输出 | 与课程的联系 |
|---|---|---|
| 图像分类 | 整张图属于哪些预定义类别 | 本练习判断蚂蚁或蜜蜂 |
| 目标检测 | 多个目标的类别与位置框 | 课程人脸检测还要解析框和执行 NMS |
| 语义分割 | 每个像素的类别 | 输出通常保留空间维度 |

本练习是**单标签二分类**：一张图给出一个真实类别，用两个输出得分进行比较。训练样本没有“未知物体”类别，模型也不会自然获得可靠的陌生物体拒识能力；它可能对无关图片仍给出很高的蚂蚁或蜜蜂分数。

ResNet 是模型家族，ResNet18 是其中一种网络结构，ImageNet 是数据集。模型结构和数据集不是同一类东西；同一种结构可以在不同数据集上训练。

## 2. 图片怎样变成模型输入

### 2.1 像素、通道和张量

一张高 224、宽 224 的 RGB 图像可表示为三个颜色通道的数值数组。常见文件读取结果按 HWC 排列，即 `[高, 宽, 通道]`；本练习的 PyTorch 模型按 NCHW 排列：

| 字母 | 含义 | 本练习示例 |
|---|---|---|
| N | 一批图片的数量 | 16 |
| C | 通道数 | RGB 为 3 |
| H、W | 高和宽 | 224、224 |

因此一个训练批次通常为 `[16, 3, 224, 224]`，最后一批可能不足 16 张。张量可以先理解为带有类型、形状和设备信息的多维数组；PyTorch 还能够跟踪由它组成的计算，以便自动求梯度。

一张前处理后的图为 `[3,224,224]`，`unsqueeze(0)` 只增加一个长度为 1 的批次轴，得到 `[1,3,224,224]`，不会复制出另一张图片。

### 2.2 为什么必须复用预训练的输入规则

模型学习的是数值模式。同一张图若换了 RGB/BGR 顺序，或把原本 0～1 的数值改成 0～255，参数看到的输入就变了。

本练习使用 `IMAGENET1K_V1` 权重所带的 `weights.transforms()`：按短边缩放到 256，再中心裁剪到 224×224，转换数值并按 RGB 通道的既定均值、标准差做标准化。它不是直接把任何长宽比的图都拉伸为 256×256。这些具体规则可查 [Torchvision 权重说明](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html)。

单个通道的标准化形式是：

$$
x' = \frac{x-\mu}{\sigma}
$$

这里的均值和标准差来自预训练约定，不是每来一张图就重新计算。与表格学习中的 `StandardScaler` 公式相似，但统计量的来源不同。

### 2.3 数据增强与前处理的区别

随机水平翻转为训练增加变化，鼓励模型不要依赖对象朝向。它通常不应改变标签；对左右手、方向箭头等任务，翻转就可能破坏标签语义。

本练习只有训练集随机翻转，验证和测试使用确定性的前处理。这样前后模型在同一评估图像上比较时，输入不会因增强而随机变化。

## 3. CNN 为什么能从图片中提取特征

### 3.1 卷积：同一组局部规则在不同位置复用

把一个 3×3 卷积核理解为 9 个可学习系数。它在图片不同位置上，对附近数值做乘法、求和，形成新的特征图。多通道时，一个输出通道还会合并所有输入通道的信息。

例如，忽略偏置和激活，一个窗口为：

```text
输入窗口         系数
1 2 3            0  0  0
4 5 6           -1  0  1
7 8 9            0  0  0
```

结果为 `-4 + 6 = 2`，表示这个局部位置的左右数值差异。实际卷积核由训练得到，并非人工把每个核指定成“找边缘”。

共享系数减少了参数，也允许在不同位置检测相似局部模式。但这不意味着网络对任意旋转、缩放或位置变化都完全不敏感。

### 3.2 读懂网络中的几个组件

| 组件 | 主要作用 | 常见误解 |
|---|---|---|
| Conv2d | 学习局部特征与通道组合 | 输出通道不是新的 RGB 颜色 |
| ReLU | 将负数变成 0，引入非线性 | 没有非线性的线性层堆叠仍相当于线性映射 |
| stride | 控制卷积核移动步长，可缩小空间尺寸 | 下采样不是单纯减少文件大小 |
| padding | 在边界补值，控制输出尺寸和边界处理 | 不等同于文本批次的 PAD token |
| MaxPool | 在局部区域取最大值，降低空间分辨率 | 它本身通常没有学习参数 |
| BatchNorm | 训练/评估时按各自规则规范化中间特征 | 不等于图像输入标准化 |
| 全局平均池化 | 将每个通道的空间特征汇总成一个数 | 它汇总的是特征图，不是原始 RGB 均值 |
| Linear / fc | 将特征向量映射成各类别的得分 | 输出得分不必已经是概率 |

较早层往往提取局部模式，较深层组合更复杂的模式；这是一种理解方式，不保证某个通道恰好对应“蚂蚁腿”这样可命名的对象部件。

## 4. ResNet18 是什么

### 4.1 残差连接：学习在输入上添加多少变化

ResNet 是 Residual Network，即残差网络。普通堆叠层直接学习某个变换，残差块让主分支学习一个增量，再与捷径分支相加：

$$
y = \operatorname{ReLU}(F(x)+x)
$$

如果输入输出形状不同，捷径分支需要投影得到匹配形状，不能直接相加。加法也不是把两份数据在通道方向拼接。

捷径为信息与梯度提供了较直接的路径，让深层网络更容易优化。它不能保证任何深度都能成功训练，也不保证不会过拟合。见 [ResNet 原论文](https://arxiv.org/abs/1512.03385)。

### 4.2 “18”与 layer4 分别指什么

ResNet18 的通常计数方式是：入口 1 个卷积层，加 8 个 BasicBlock 各 2 个主分支卷积层，再加 1 个全连接层，共 18 个；BN、ReLU、池化以及捷径投影不按这个命名口径逐个累加。

Torchvision 将 8 个 BasicBlock 分为四组，每组 2 个。`layer4` 是第四组残差块，不是整个模型的第四个单独算子。

以本练习 `[N,3,224,224]` 输入为例，主要形状变化如下：

| 阶段 | 输出形状 | 含义 |
|---|---|---|
| 输入 | `[N,3,224,224]` | 标准化 RGB 图像 |
| conv1、BN、ReLU | `[N,64,112,112]` | 入口特征 |
| maxpool | `[N,64,56,56]` | 降低空间分辨率 |
| layer1 | `[N,64,56,56]` | 2 个残差块 |
| layer2 | `[N,128,28,28]` | 通道增多、空间变小 |
| layer3 | `[N,256,14,14]` | 继续组合特征 |
| layer4 | `[N,512,7,7]` | 最后一组残差块 |
| avgpool、flatten | `[N,512]` | 每图 512 个特征 |
| 原始 fc / 本练习新 fc | `[N,1000]` / `[N,2]` | 类别得分 |

结构细节以 [Torchvision ResNet 实现](https://docs.pytorch.org/vision/0.20/_modules/torchvision/models/resnet.html)为准。原始 ImageNet 版本约有 1170 万参数；替换分类层后，参数总数也会改变。

### 4.3 为什么适合作为入门例子

它结构清楚、预训练资源完善，可以明确观察“冻结骨干、替换分类头、解冻最后一组”。ResNet34、ResNet50 是同家族的其他结构，ResNet50 使用不同的残差块设计。MobileNet、EfficientNet、Vision Transformer 等也可用于视觉任务；模型选择需要结合数据、硬件、质量和延迟实测，不能只按层数比较优劣。

## 5. 迁移学习为什么可能有效

预训练已经让参数适应大量视觉数据。我们希望复用其中对当前任务有用的表示，而不靠少量蚂蚁/蜜蜂图片从头学习所有视觉特征。

将网络分为：

```text
图片 → 骨干网络 backbone → 512 维特征 → 分类头 head → 两个类别得分
```

本练习的 `model.fc = nn.Linear(model.fc.in_features, 2)` 创建全新随机参数。原来 1000 类的分类能力不会通过改标签文字自动变成两类的新任务；新分类头必须学习这两类与特征的关系。

| 阶段 | 更新对象 | 为什么分阶段 |
|---|---|---|
| 只训练 head | 新 fc | 先让随机分类头学会使用已有特征 |
| 微调 | layer4 和 fc | 让后部特征进一步适应任务，使用较小步长 |

微调是迁移学习的一种做法。源数据与新任务差别太大、小数据标签不可靠、解冻范围或学习率不合适，都可能让微调退步。

## 6. logits、概率、标签与损失怎样衔接

假设类别顺序为 `['ants','bees']`，一张图的 logits 是 `[2.0,1.0]`。直接 `argmax` 得到 0，对应 ants；softmax 后约为 `[0.731,0.269]`，最高类别不变。

softmax 在这里沿**类别轴**运行，输出每行和为 1 的数值。高概率表示模型的相对判断，并非经过证明的现实可靠度；校准与分布外识别需要额外评估。

若真实标签为 0，交叉熵为：

$$
L=-\log p_0 \approx 0.313
$$

`CrossEntropyLoss` 接收原始 logits 和整数类别编号，内部完成所需的概率相关计算；不要先 softmax 再传入它。本例 labels 形状为 `[N]`，不是两列 one-hot；预测输出形状为 `[N,2]`。

## 7. 读懂 PyTorch 的训练动作

```python
# 示意一个批次的核心步骤；变量由 Notebook 的训练函数提供。
optimizer.zero_grad(set_to_none=True)  # 清除上一个批次的梯度
logits = model(images)                # 前向计算
loss = criterion(logits, labels)      # 比较预测与真实标签
loss.backward()                      # 自动计算损失对参数的梯度
optimizer.step()                     # 优化器根据梯度修改参数
```

梯度说明参数怎样影响当前损失；它不等于参数本身。一次 `step()` 是一次参数更新，一轮 epoch 通常包含多个批次更新。

还需区分三个开关：

| 操作 | 控制什么 | 不会自动完成什么 |
|---|---|---|
| `requires_grad=False` | 不为某参数求梯度 | 不自动切换 BN 的统计行为 |
| `model.eval()` | 改变 BN、Dropout 等模块的行为 | 不自动关闭所有梯度记录 |
| `inference_mode()` | 推理时关闭自动求导相关开销 | 不负责调用 eval |

参数只有进入优化器且具有可用梯度时，才会在通常的更新流程中被优化。本练习第二阶段重建优化器，明确纳入 layer4；只改 `requires_grad` 而仍使用只含 fc 的旧优化器，layer4 不会被它更新。

BN 还有运行均值/方差这样的**缓冲状态**，不是普通可训练权重。本例训练时固定 BN 的统计行为，以减少小批次统计的扰动；解冻组内 BN 的可训练缩放、偏移仍可更新。

## 8. 怎样判断练习学到了什么

验证集用于选 epoch 和候选阶段，最终测试集用于选择完成后的评估。先比较权重快照，可确认预期的层确实更新；但“发生参数更新”本身不证明效果改善。

本练习图片包源于 ImageNet 的小子集，预训练也使用 ImageNet，因此测试只是本次微调时保留的样本，不保证预训练阶段从未见过。不能把高分宣传为完全陌生图片上的泛化能力。

如果训练损失下降而验证损失上升，检查过拟合、学习率、数据增强和标签质量；不要根据测试分数反复试参。类别不平衡时，还要看各类召回和混淆矩阵，不能只看整体准确率。

## 9. 保存了什么，如何接回课程推理

`state_dict` 保存参数与缓冲状态，不包含自动理解图片的所有规则。本练习额外保存网络名称、类别顺序和前处理配置。恢复时先创建匹配的结构，再载入状态，重建输入规则。

`.pt` 是此例的 PyTorch 检查点；ONNX 表达计算图及参数，用于跨运行时部署。二者不是改后缀就能互换。若需要导出 ONNX，应另外验证导出前后的形状、类别解释和数值接近程度。

## 11. 自测与参考解释

1. **`[8,512,7,7]` 中的 512 是图片数吗？** 不是，是每张图的特征通道数；图片数是 8。
2. **为什么不能只把 1000 个标签名称改成两个？** 输出层仍有 1000 个得分及原任务的参数，需要匹配新任务的输出结构与训练。
3. **冻结参数后还要关心 BN 吗？** 要，运行统计属于缓冲状态，训练模式仍可能修改它们。
4. **微调后分数下降，代码一定错了吗？** 不一定；既要排查实现，也要考虑数据少、任务差异和优化设置。
5. **为什么推理用 `[0]`？** 单图也有批次轴；softmax 后 `[1,2]` 的第 0 行才是这张图的两类概率。
